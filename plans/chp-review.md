## 1 逐条对照

### 1.1 「列表第一个都应该是默认的推荐配置，而不是按大小排列的」

**现状.** 枚举不是手写的，是 `capabilities.sizes()` 按 `budgets × aspects` 的**书写顺序**算出来的：

```python
for budget in domain.get("budgets") or []:      # 外层
    for aspect in domain.get("aspects") or []:  # 内层
```

实机四项都对得上你的说法：`quick` / `inpaint` 首项 `[512,512]`、`upscale` 首项 `[1024,1024]`、`render` 首项 `[1024,1024]`；
而 `defaults.size` 分别是 `[512,512] / [512,512] / [1024,1024] / [1024,1024]`。

**差在哪.** 「首项 = 推荐」**今天成立，但它是书写顺序的副产品**：`defaults.size` 是能力表里另一处手写的值，
枚举顺序由 `budgets` / `aspects` 的先后决定。两处只要有一处被人改过，就出现「菜单第一项不是默认值」——而且**没有任何测试会发现**。
`upscale` 最能说明问题：`budgets: [1048576, 4194304]` 恰好是升序，也就是它**现在是按大小排的**，只是刚好和推荐值重合。

**这不是推的，是量出来的**（把 `quick` / `inpaint` 的 `aspects` 换成 `[[4,3],[1,1],[3,4]]`，其余一字不动）：

```
baseline  first=quick[512,512] inpaint[512,512] upscale[1024,1024] render[1024,1024]   全部 SAME
mutant    first=quick[576,384] inpaint[576,384]           default 仍是 [512,512]         DIFFERENT
          tests/test_spec.py  rc=0 —— 官方离线合同测试在变体上照样全绿
```

也就是说：**枚举首项可以在没有任何测试变红的情况下离开推荐值。**
（顺带说明上一轮 `preset()` 那条改动值在哪：同一个变体下，旧写法 `sizes[0]` 会锁成 576 × 384，
而 `defaults.size` 说 512 × 512 —— 正是 `stretched_reference` 要拦的那类静默变形。）

**建议.** 二选一，别两个都要：
- **(a) 把它变成规则**：在 `capabilities.py` 里让 `defaults.size` 不再是独立手写值，或者加一条契约测试
  `entry["values"]["size"][0] == entry["defaults"]["size"]`（`tests/test_spec.py` 已在测 `values.size` 的形状，加一行即可），
  并在规范 §3.2 写明「枚举首项恒等于 `defaults.size`」。
- **(b) 干脆不依赖它**：规范写明「`values.size` 只是一张候选菜单，**顺序无意义**；要默认值请读 `defaults.size`」。
  这条路更符合你的第二条原则（画幅由 happ 选），代价是 `sizes()` 的书写顺序从此完全无意义。

我倾向 **(a) + (b) 一起**：声明顺序无意义（客户端不许读 `sizes[0]`），同时用测试钉住「首项就是推荐值」以便人读。

### 1.2 「包括分辨率和比例和更多参数可不可以在界面上选择，这是 happ 自己的逻辑」

**现状 —— 两个客户端各自的选择（都合规）.**

| | 画幅 | 步数 / 参考权重 | 界面 |
|---|---|---|---|
| hamdraw | 在能力公布的 `values.size` 里**挑方形那一张**（`sizes.filter(p => p[0] === p[1])[0]`），取不到才退 `sizes[0]` | 取 `defaults.steps` / `defaults.ref_strength`（quick / inpaint 再乘一道画布上的「创造力」滑竿） | **锁死**，设置页只把画幅当只读行印出来 |
| chataxi | **按分数**在公布的 `values.size` 里挑最接近 9:16、长边 1344 的一张（`PREFERRED_SIZE`） | 取 `defaults.steps` / `defaults.ref_strength` | 画幅/步数不显示、不可改 |

这正是你说的「都是 happ 的选择」，**这部分没有差异**。

**差在哪.** 差在**这条边界没有写进规范**，而且被客户端各自复制了一份「合法性判断」：

- `hamdraw/app/services/providers.js` `validate()` 里对 chp 硬写 `256 ≤ 边 ≤ 2048`。这是**客户端重抄服务端规则**，
  而真规则是每种能力的 `size_domain`（`quick` 长边 ≤ 768、`render` 长边 ≤ 1536、`upscale` ≤ 2560）——已经对不上。
- 同一个文件的 `lockedCanvasError()` 又在客户端复刻一遍「这张能力只接受公布的这几张」。
  它在客户端**比服务端更严**：`fits()` 收清单外的合法画幅，而这里会先把它拦下来。

**建议.** 规范补一段「**客户端负责选，服务端负责判**」：客户端可以读 `size_domain` 给自己的菜单算一张，
但**不得**自己下「不合法」的结论——判据只有服务端那一个（`unsupported_size`）。
相应地，客户端里那两处复刻的规则应该缩成「正整数」的形态检查。

### 1.3 「中间 ComfyUI 节点过程应该可以完全用户自己定制，chp 提供的只是官方参考工作流」

**现状.** 规范 §0 已经写了「绑定的模型名、采样参数、节点图都是针对特定模型的建议，可以被替换而不改变本规范」，
所以 **「换实现」这一层是允许的**。但插件里**没有「用户自带工作流」这个口子**：`families.FAMILIES` 是一张写死的映射表，
`families/__init__.py` 明说「两个家族不需要注册机制」，`nodes.py` 也说「nothing patches a user-supplied workflow any more」。

**差在哪.** 而且这条**是上一轮主动删掉的**：`plans/chp-plan.md` §P5 的表格里有一行——
「节点描述同步更新(删掉"仍接受自定义工作流"这句已失效的话)」。也就是说：**以前有，被当作「已失效」清理了。**
你的说法（「可以完全用户自己定制」）比现在允许的（「可以被另一个实现替换」）更强。这两件事要分开说：
- 「换一个家族模块 / 换一份出厂图」= 已经是规范允许的**实现内部**的事（改 Python，不走接口）；
- 「丢一个 API-format JSON 进来覆盖出厂图」= 现在**没有**，而且和 §8「不做插件化的家族注册机制」直接冲突。

**建议（需要你定）.** 如果你要的是后者，代价是插件要定义一个「工作流来源」的设置项（一个文件路径 + 一份输入映射约定）
——那是新的能力面，不是收敛。如果你要的只是前者，就把规范 §0 那句「可以被替换」写清楚到「**怎么替换、替换后哪些字段不许变**」，
并在插件说明里把「出厂图 = 官方参考」写出来，不再说「唯一路径」。

### 1.4 「每个场景分类对应的规则分类是固定的；fast 是 txt-ref-2-img，inpaint 是 txt-msk-ref-2-img」

**现状.** 四个能力 `signature` **全是 `txt-ref2img`**，`input` 全是同一份 `txt-ref2img/v1`（实机确认：`input_schemas` 只有 1 份）。
`inpaint` 的蒙版需求是靠能力里的 `needs: {prompt, image, mask: true}` 表达的。

**差在哪 —— 这是全篇最实的一处.**
`signature` 是规范里**唯一**声明「吃什么吐什么」的机器可读字段（§2），而它现在**描述不了 `inpaint`**：
一个按签名分支的客户端会把它当「文本 + 一张参考图」，然后不发蒙版，拿到 `bad_mask`。
换句话说 **`needs.mask` 在替签名干活**，签名退化成了装饰。你说的 `txt-msk-ref2img` 目前**不存在**
（`signature` 语法本身支持它：`<模态> ::= txt | img | mask | ref | refs`，`txt-msk-ref2img` 只在最后一个 `2` 处切分，合法）。

**建议（需要你定，因为触碰冻结字段）.** 规范 §0 第 3 条明写「不改已发布能力的 `signature` / `input`」，所以有三条路：
1. **只加 schema、不动签名**：新增 `txt-msk-ref2img/v1`（比 `txt-ref2img/v1` 多一个必填 `mask_base64`），
   `inpaint` 的 `input` 指过去，`signature` 留到 `chp/2` 再改。缺点：签名和 schema 暂时不一致。
2. **`spec` 升到 `chp/2`**：一次把 `inpaint.signature` 改成 `txt-msk-ref2img`、`input` 指到新 schema。
   干净，但按 §0 第 3 条这是大版本动作，要有迁移说明（老客户端读 `chp/1` 见 `spec != "chp/1"` 就该知道自己不认识）。
3. **什么都不改**，只在规范里写明「签名只描述主要模态，细节看 `needs`」。**不推荐** —— 那等于承认签名不可依赖。

我倾向 **2**：`spec` 生来就是干这个的，而且现在只有两个客户端，迁移成本最低。

### 1.5 「规则必要参数尽可能收敛到必要；模型没提供的要在中间工作流里模拟出来」

**现状 —— 这条做得最到位，一处例外.**

- 唯一的「规则必须参数」是 `ref_strength`（`0.05–0.95`，方向冻结），两个家族各按自己的模型给出**不同机制**：
  `checkpoint` 家族是 `denoise = 1 − ref_strength`；`qwen_image` 家族没有可保留的初始 latent，就改成**柔化参考图**（`ImageBlur`）。
  规范 §4.1 把这件事写成了「同一字段、机制不同，都合规」的样例。**这就是你要的「模型没提供就自己模拟」。**
- 蒙版**没有**模糊参数（你点名要的那条），由 happ 自己控制 —— 符合。

**例外：`grow_mask_by` —— 已作废，2026-09-29 整条删除.**

它当时的状态是「在 schema 里、不在规范里、没人用」三种都不是：对外 schema 有它
（`txt-ref2img/v1.properties.grow_mask_by`，0–64），规范 §4 的字段表里没有这一行（第 6 条差异），
`create_job` 照收照夹边界，两个 family 照收形参 —— **然后没有任何一个图节点读它**。
外扩真正发生在**客户端**：hamdraw 的 `canvas-io.js` 把笔迹加粗（`MASK_GROW`），请求里发的是 `0`，
`providers.js` 写明了为什么不能交给服务端 ——「a server side grow dilates the mask until it is flat again,
which is exactly the hard edge the feather removes」。

**当时给的两条建议都没被采纳**：收进 `txt-msk-ref2img` 规则参数 / 判为「不属于规则」走扩展通道。
业主的判断是直接删 —— 它没有任何消费者，而它想做的那件事客户端已经在做，**而且必须由客户端做**
（服务端膨胀会把前端羽化出来的软边重新压平成硬边，方向正好相反）。落地范围见
[`chp-v2-plan.md`](./chp-v2-plan.md) §1.3 与 §2。

### 1.6 「chp 还应该支持暴露模型的扩展参数……如果模型想把这些非必要参数暴露给 happ 修改，那么就走扩展参数通道」

**现状 —— 通道不存在.**

- 唯一的「额外旋钮」是**服务端设置文件**里的 `families.qwen_image_21: {cache_device, cache_dtype, reference_edge}`，
  由 `qwen_image.OPTIONS` 声明、`families.build(options=...)` 转交。**happ 碰不到它，也不该碰到**——
  这是**部署调优**（某台机器显存小就写 `int8`），规范 §8 的「去设备化」正是这个意思（出厂默认不带部署选择）。
- **请求体没有任何扩展位**：`server.create_job` 只读它点名的那几个字段，**其余字段静默丢弃**。
  更糟的是它不把丢弃的字段报回去 —— 而规范 §1.4 明写 `ignored` 的用途就是「客户端据此提示用户，
  而不是让用户以为自己设的参数生效了」。**一个客户端今天发 `{"steps_hint": 30}` 会得到零反馈。**

**建议（需要你定形状）.** 三层要分清，这是这段讨论最值钱的产出：

| 层 | 谁改 | 例子 | 现在的载体 |
|---|---|---|---|
| 规则必要参数 | 规范冻结 | `ref_strength` | 共享 schema |
| **模型扩展参数** | **happ 按能力公布的清单改** | 步数上限以外的采样器偏好、`reference_edge` 这类模型自带旋钮 | **没有** |
| 部署调优 | 运维改设置文件 | `cache_dtype`、翻译后端地址 | `hamdraw_settings.json` |

最小可做的形状（不碰冻结字段、只加）：
1. 能力条目里加一个 `params`（或 `extensions`）数组，每项 `{name, type, range/default, label, help}` —— 与 `values` / `defaults` 同构；
2. 共享 schema 里加一个可选对象 `params: {…}`（`additionalProperties: true`），或直接把这些名字提升为一级可选字段；
3. `server.create_job` 按能力声明的清单**白名单**过滤后转给家族；**不在清单里的字段一律进 `job.ignored`**。
   第 3 条**即使不做第 1、2 条也该做**：它独立地把「静默丢弃」补成「如实回报」。

4. 规范 §6 错误表补 `stretched_reference` / `unsupported_task`（**本轮已补**）。（本条原来的前半句「§4 字段表补 `grow_mask_by`」已作废 —— 它整条删了，见 §1.5）
5. `tests/test_spec.py` 加一条 `values.size[0] == defaults.size` 的守卫（第 4 条差异）；
6. 规范补一句「`values.size` 的顺序无意义，默认值是 `defaults.size`」。

**需要你先定，再动：**
